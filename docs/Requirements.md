## 1. 핵심 결론

DAH 2026 예선은 코드 제출 대회라기보다, 방산 환경에서의 공격 시나리오, 방어 아키텍처, AI 에이전트 설계 및 구현 역량을 보고서로 증명하는 온라인 심사다.

최종적으로 제출해야 하는 것은 아래 2개다.

- 예선 보고서 PDF: 필수, 최대 50MB
- 부가자료 다운로드 링크: 필수, 소스 코드 및 실행 매뉴얼 ZIP을 외부 클라우드에 업로드한 링크

가장 중요한 점수 항목은 다음 3개다.

- 공격 시나리오 설계: 30점
- 방어 전략 수립: 25점
- AI 에이전트 아키텍처: 25점

즉, 단순한 아이디어 문서가 아니라 "방산 도메인에 맞는 현실적 공격", "그 공격과 정확히 맞물리는 방어 체계", "공격/방어를 수행하거나 보조하는 AI 에이전트 구조와 구현 증거"를 만들어야 한다.

| 항목 | 배점 | 평가 기준 |
|---|---:|---|
| 공격 시나리오 설계 | 30점 | 공격 전략의 창의성과 기술적 완성도 |

4. 문서 형식과 출처 표기로 자동 평가 점수를 잃지 않는다.

## 7. 지금 해야 할 일

### 7.1 도메인과 시나리오 확정

먼저 방산 도메인 하나를 명확히 고른다.

선택 후보:

- UAV: 무인기, 드론, 정찰/타격 임무, 지상관제소, 영상/텔레메트리 링크
- UGV: 지상 무인차량, 자율주행, 원격제어, 센서 융합, 임무 경로
- 위성통신: 지휘통제 통신, 링크 교란, 인증, 지연/손실 환경

권장 방향:

- 대회 안내서가 UAV, UGV, 위성통신을 예시로 들었으므로 이 중 하나를 선택하면 평가자가 이해하기 쉽다.
- 시간이 부족하면 UAV가 가장 쓰기 쉽다. 공격 표면이 센서, GPS, 통신, 영상, 지상관제소, 임무계획 파일 등으로 다양하고 AI 에이전트와 연결하기 좋다.

결정해야 할 것:

- 보호 대상 시스템
- 운용 환경
- 공격자 목표
- 공격 성공 조건
- 방어 성공 조건
- 시뮬레이션 또는 프로토타입 범위

### 7.2 공격 시나리오 작성

공격 시나리오는 최소한 아래 구조로 작성한다.

- 배경: 어떤 방산 임무 환경인가
- 자산: 보호해야 할 시스템, 데이터, 통신, 모델
- 공격자: 능력, 접근 권한, 제약 조건
- 공격 표면: 네트워크, 센서, AI 모델, 관제 시스템, 로그, 인증 체계
- 공격 체인:
  - 정찰
  - 초기 침투 또는 접근
  - 권한 확대 또는 우회
  - AI 기반 자동화/의사결정
  - 임무 교란
  - 은닉 또는 지속성
- 피해 영향:
  - 임무 실패
  - 오탐/미탐
  - 경로 이탈
  - 통신 장애
  - 데이터 위변조
  - 의사결정 지연
- 현실성 근거:
  - 방산 운용 제약
  - 네트워크 단절/저대역폭/지연
  - 실시간성
  - 제한된 컴퓨팅 자원
  - 안전성 요구

주의:

- 단순 "해킹한다" 수준이면 낮은 점수를 받을 가능성이 크다.
- 방산 환경의 특수성, 공격 표면, 단계별 절차가 구체적이어야 한다.
- 실제 악용 가능한 세부 침해 절차를 과도하게 쓰기보다, 평가 가능한 수준의 기술적 설계와 위험 분석에 집중한다.

### 7.3 방어 아키텍처 작성

방어 전략은 공격 시나리오의 각 단계에 대응해야 한다.

필수 포함 요소:

- 탐지: 이상 징후, 로그, 센서 데이터, 네트워크 이벤트, 모델 출력 모니터링
- 차단: 정책 기반 차단, 인증 강화, 격리, fallback 제어, rate limit
- 복구: 안전 모드 전환, 백업 경로, 모델 롤백, 설정 복원, 임무 재계획
- 검증: 공격 전/후 비교, 탐지율, 오탐률, 대응 시간, 복구 시간

권장 표:

| 공격 단계 | 위협 | 탐지 방법 | 차단 방법 | 복구 방법 | AI 에이전트 역할 |
|---|---|---|---|---|---|

이 표 하나가 공격, 방어, AI 에이전트의 연결성을 보여주는 핵심 증거가 될 수 있다.

### 7.4 AI 에이전트 설계

AI 에이전트는 구체적이어야 한다.

권장 에이전트 구성:

- Threat Modeling Agent
  - 방산 임무 환경과 자산 정보를 받아 공격 표면과 위협을 정리
- Attack Simulation Agent
  - 제한된 실험 환경에서 공격 시나리오를 자동 실행하거나 재현
- Detection Agent
  - 로그, 센서, 네트워크 이벤트를 분석해 이상 징후 탐지
- Response Agent
  - 탐지 결과에 따라 차단/격리/복구 액션 추천 또는 실행
- Report Agent
  - 공격/방어 실험 결과를 요약하고 증거를 정리

보고서에 반드시 들어가야 할 것:

- 에이전트별 입력
- 에이전트별 출력
- 에이전트별 도구
- 에이전트 간 메시지 흐름
- 의사결정 기준
- 실패 시 fallback
- 보안 통제
- 테스트 결과

기술 스택 예시:

- Python
- LLM API 또는 로컬 모델
- LangGraph, LangChain, CrewAI 등 에이전트 프레임워크
- FastAPI 또는 CLI
- Docker
- SQLite/JSONL 로그
- 네트워크/센서 이벤트 시뮬레이터
- matplotlib/mermaid/diagrams.net 등 시각화 도구

### 7.5 프로토타입 구현

완성도가 높은 실제 시스템이 아니어도 된다. 다만 "설계만 했다"보다 "작동하는 축소 구현이 있다"가 훨씬 유리하다.

최소 구현 범위:

- 공격 이벤트 샘플 생성
- 방어 탐지 로직 실행
- AI 에이전트가 이벤트를 분석
- 대응 방안 또는 자동 대응 결과 생성
- 로그와 결과 리포트 저장

권장 실행 흐름:

```text
1. 시나리오 설정 파일 로드
2. 공격 이벤트 생성
3. Detection Agent가 이상 탐지
4. Response Agent가 차단/복구 액션 결정
5. 결과 로그 저장
6. 요약 리포트 생성
```

보고서에 넣을 증거:

- 실행 화면 스크린샷
- 주요 로그
- 탐지 결과 표
- 코드 스니펫
- 아키텍처 다이어그램
- GitHub 또는 클라우드 저장소 링크
- 가능하면 unlisted 데모 영상 링크

## 9. 고득점 전략

### 9.1 공격 시나리오 30점

고득점 포인트:

- 실제 방산 운용 환경을 정확히 반영
- 공격 목표와 성공 조건이 명확
- 공격 표면이 구체적
- 단계별 공격 흐름이 논리적
- AI가 공격을 어떻게 보조하거나 자동화하는지 설명
- 현실적인 제약 조건을 반영

피해야 할 것:

- 일반 IT 보안 시나리오를 방산 이름만 붙여서 제출
- 공격 단계가 추상적인 설명에 머무름
- 공격 성공 기준이 없음
- 방어 전략과 연결되지 않음

### 9.2 방어 전략 25점

고득점 포인트:

- 공격 단계별 탐지/차단/복구 매핑
- 실시간 운용 가능성
- 장애나 오탐 발생 시 fallback
- 로그와 센서 데이터 기반 탐지
- 방산 환경의 저대역폭, 지연, 폐쇄망, 안전성 요구 고려

피해야 할 것:

- "AI로 탐지한다"처럼 추상적으로 작성
- 복구 전략이 없음
- 공격 시나리오와 무관한 방어 기술 나열

### 9.3 AI 에이전트 아키텍처 25점

고득점 포인트:

- 에이전트별 책임이 명확
- 입력/출력/도구/상태 관리가 구체적
- 에이전트 간 협력 흐름이 있음
- 프로토타입 구현 증거가 있음
- 테스트 결과가 있음
- 다이어그램이 있음

피해야 할 것:

- LLM을 쓴다는 말만 있고 구조가 없음
- 에이전트가 실제 공격/방어 시나리오와 연결되지 않음
- 구현 결과가 없음

### 9.4 팀 역량 10점

고득점 포인트:

- 팀원별 역할이 중복 없이 명확
- 보안, AI, 시스템, 문서화, 실험 담당이 분리됨
- 관련 경험 또는 수상 이력 명시
- 각 팀원의 기여물이 보고서/코드와 연결됨

### 9.5 문서 완성도 10점

고득점 포인트:

- 필수 항목 순서 준수
- 표와 그림 적극 사용
- 모든 표/그림/코드 출처 표기
- 참고문헌 일관성
